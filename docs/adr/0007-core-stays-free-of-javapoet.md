# The core stays free of JavaPoet; the wildcard helpers stay duplicated in the backends

The architecture review of #203 proposed moving the identical `typeVarsToWildcards` and `typeArgumentToWildcard` helpers of `MatcherGenerator` and `AssertionGenerator` into `matcher-generator-core`, so that the backends would share them. The proposal was dropped, because those helpers build JavaPoet types and the core would then need JavaPoet on its classpath, which [ADR 0001](0001-shared-property-model-and-backend-spi.md) keeps for the backends alone. The helpers therefore stay in the two backends, duplicated on purpose; the core has no JavaPoet dependency, and the [ADR 0004](0004-kotlin-dsl-backend-on-top-of-hamcrest.md) Kotlin backend does not change that, since KotlinPoet is likewise a backend concern. The rule is pinned by `CoreDependencyRulesTest`, so that a later review does not propose the move again without revisiting this decision.
