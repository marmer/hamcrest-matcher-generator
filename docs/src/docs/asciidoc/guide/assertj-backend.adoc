= AssertJ backend
:description: The generated AssertJ assertions: per-property checks with readable messages, nested assertions, the completeness check and the whole-object comparison with usingRecursiveComparison.
:page-order: 4

For every configured type the AssertJ backend generates an assertion class, `CustomerAssert` for `Customer`. Its static `assertThat` returns the assertion, and each property gets a `hasX` method that takes the expected value. The assertion class extends AssertJ's object assertion, so AssertJ's own assertions stay available next to the generated ones.

The dependency is the `assertj-assertion-generator` artifact, which the link:getting-started.html[getting started chapter] declares next to the Hamcrest one.

== The whole object

Sometimes an assertion should cover the whole object, not single properties. AssertJ's `usingRecursiveComparison()` does that in one step: it compares every field of the actual object with the expected one, nested objects included. Every generated assertion inherits it, so it works on `CustomerAssert` without any generated code:

[source,java]
----
include::../../../../../example-maven-java-assertj/src/test/java/example/assertj/CustomerAssertTest.java[tag=whole-object,indent=0]
----

Use the generated `hasX` methods when a test should name the properties it checks, with a message for each. Use `usingRecursiveComparison()` when the expected object is at hand and every field should match. The completeness check gives the same guarantee for properties that are checked one by one.
