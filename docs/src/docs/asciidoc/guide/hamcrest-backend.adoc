= Hamcrest backend
:description: The generated Hamcrest matchers: equality and matcher checks per property, resetting and ignoring checks, the completeness check and reference objects.
:page-order: 3

For every configured type the Hamcrest backend generates a matcher, `CustomerMatcher` for `Customer`, with two factory methods: `isCustomer()` for a matcher that checks properties one by one, and `isCustomerLike(reference)` for a matcher that compares every property with a reference object. The matcher works with Hamcrest's own `assertThat`.

== Completeness check

The completeness check turns a matcher into a check of every property. It is off by default. When you call `checkingAllProperties()`, the assertion fails unless every property is either checked or ignored. An ignored property is one you name with `ignoringX()`, so the decision not to check it is visible in the test:

[source,java]
----
include::../../../../../example-maven-java-hamcrest/src/test/java/example/hamcrest/CustomerMatcherTest.java[tag=completeness-check,indent=0]
----

When a property was neither checked nor ignored, the failure names it. A property added to the model later therefore fails the tests that opt in, until someone checks or ignores it. The link:completeness-check.html[completeness check chapter] covers the rule for both backends and the Kotlin DSL.

== Reference objects

The `isCustomerLike(reference)` method takes a reference object and compares every property with it, nested properties included. The example passes because the actual customer equals the reference. A reference that differs in a nested property fails and names that property, as the `address.city` check in `CustomerMatcherTest` shows:

[source,java]
----
include::../../../../../example-maven-java-hamcrest/src/test/java/example/hamcrest/CustomerMatcherTest.java[tag=reference-object,indent=0]
----

A deep comparison applies only to properties whose type has a matcher generated in the same processing round. A property whose type is a class of yours without a generated matcher in the round, for example because it is configured in another round or compilation, is compared with `equals` instead. Run the compiler with `-Amatchergenerator.verbose` to get one note per such property that names the property and the type.
