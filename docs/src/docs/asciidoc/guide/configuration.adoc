= Configuration
:description: Choose the types to generate for with the configuration annotation, exclude types and set the package of the generated code.
:page-order: 2

One annotation, `GenerateMatchers`, tells the processor which types to generate for. Put it on a class of your choice. The backends on the processor path both read it, so a configuration selects the same types for the Hamcrest matchers and the AssertJ assertions.

== Selecting types

The annotation's value lists package names and fully qualified class names. A package entry selects every class in the package, and a class entry selects exactly that class:

This configuration generates a matcher for every model class in `example.hamcrest.model`. The model classes can be beans with getters, records or Kotlin classes: the processor reads bean getters, record component accessors and Kotlin getters.

== Excluding types

The annotation's `exclude` value takes the same kinds of entries and removes types from the selection. A package entry excludes every configured type in it, and a class entry excludes that one type. An entry that matches no configured type is reported as a warning, so a misspelled name does not pass silently.

== Package of the generated types

The generation setting `packageConfig` decides the package of the generated types. Its value is a prefix, so the generated code of a type can live in a package other than the one of the type. The javadoc of the annotation gives the rule with examples: the prefix `some.praefix.` turns the package `some.pck` of `some.pck.SomeType` into `some.praefix.some.pck`, and an empty value keeps the package of the type.

== Where the generated code goes

The Maven compiler writes the generated sources of a configuration in `src/main/java` to `target/generated-sources/annotations`, and those of a configuration in `src/test/java` to `target/generated-test-sources/test-annotations`. The example modules keep their configuration in `src/main/java`, so their matchers and assertions are available to test code as well as to production code.
