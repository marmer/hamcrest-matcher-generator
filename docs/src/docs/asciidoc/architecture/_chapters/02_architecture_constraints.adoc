[[section-architecture-constraints]]
== Architecture Constraints

[options="header",cols="1,4"]
|===
| Constraint | Background

| Java 17 baseline
| The processor, the runtime artifacts and the generated code run on Java 17 and later, so records are always supported (see <<adr-0005,ADR 0005>>).

| 5.x source compatibility
| Tests written against 5.x keep compiling after a version bump alone, provided the project already builds on JDK 17 or later (users on Java 11 stay on 5.x): same matcher class names, packages and `isX()`/`withFoo`/`resetFoo` methods. The artifact switch is covered by bridge jars under the old coordinates; anything else goes into the migration guide (see <<adr-0002,ADR 0002>>).

| Apache-2.0 license
| Every published artifact stays under the Apache License 2.0, with a short `NOTICE` file and an SPDX header in every source file. Generated code belongs to the user and carries no license header, so the generator's templates must never contain text copied from third-party code. Dependencies that end up on a user's classpath may only use permissive licenses (Apache-2.0, MIT, BSD-2-Clause, BSD-3-Clause); the build checks this.

| Documentation built on JDK 21 or later
| The documentation module renders this documentation with Structurizr, whose current libraries need Java 21. A JDK 17 build skips the module (see <<adr-0003,ADR 0003>>).

| Conventional Commits
| The title of every pull request follows Conventional Commits, because the squash-merged title is the commit that release-please reads to decide the next version (see <<section-deployment-view,chapter 7>>).
|===
