# Wayfinding process rules

Process rules for wayfinder maps and their tickets, used by `/wayfinder`. A map's Notes hold the project's decisions; this file holds how to work the map. Read **Every session** and **Merging**, plus the section for the ticket type you work on.

## Every session

- **Status view**: the `## Status` section is generated by `scripts/agents/issue-status.py <map>` (for the map `52`, run `scripts/agents/issue-status.py 52`); run it after every claim, resolution or new ticket (see `docs/agents/issue-tracker.md`). The same applies to the spec and its tickets later.

## Merging

- **Owner rule**: PRs created in wayfinder sessions are merged by the session itself (squash via `gh api -X PUT .../pulls/<n>/merge`), even with red CI. The repo has no auto-merge, so when the owner asks for a PR ("`/pr`", "PR und merge"), the PR ends merged in the same session. Vendored skills (`.agents/skills/`, `skills-lock.json`) are never modified. After a squash merge, reset the session branch to the base before new work (git fetch origin development && git checkout -B <branch> origin/development && git push --force-with-lease); otherwise its already-merged commits conflict with the squash commit in the next PR.
- **Clean branch**: every session leaves its branch with no commits outside a merged PR. At session start, check `git log --oneline origin/development..HEAD`; fold any leftover commit into a PR of its own, or name it explicitly in the PR that carries it.

## Grilling tickets

- **Skills**: grilling tickets use `grilling` + `domain-modeling`. Keep `GLOSSARY.md`/`docs/adr/` in sync with arc42 (`docs/agents/domain.md`).
- **Completion**: a round in which the owner accepts every answer and no question is left open counts as the confirmation of shared understanding; record the resolution without an extra confirmation round.

## Prototype tickets

- **Shown to the owner**: before asking for a verdict, publish an overview page as an Artifact (each candidate's code plus its real output) and link it; the owner often reviews on a phone and cannot browse branches there. Build it with `scripts/agents/prototype-page.py` from the run output.
- **On API shape** (the vendored `prototype` skill has only LOGIC and UI branches): hand-write the code the generator would emit, add a property "later", compile and run each candidate against the real libraries (classpath: `scripts/agents/prototype-classpath.sh`), and show the real javac/Hamcrest/AssertJ output. Cover the full **sample set** in the first round: flat POJO, nested POJO, record, null nested value, list, set and map of a generated type, all without `toString`. Keep the worktree at `/home/user/prototypes/<name>` (the scratchpad path changes on session restart). Examples: branches `prototype/completeness-check`, `prototype/mismatch-message-format`.

## Research tickets

- **Findings**: each closed research ticket's resolution comment gists the findings; full sources live on the unmerged `research/<name>` branches under `docs/research/` (e.g. `git fetch origin 'refs/heads/research/*:refs/remotes/origin/research/*'`).
