# KAPT configuration (Kotlin end-to-end modules)

`hamcrest-matcher-generator-endtoend-mixed-kotlin-java` and `hamcrest-matcher-generator-endtoend-plain-kotlin` run the processor through the `kotlin-maven-plugin` `test-kapt` execution into `target/generated-sources/kapt/test/`. A `build-helper-maven-plugin` `add-test-source` registers that directory as a test source root. The comment in those poms says that javac compiles only the KAPT matchers that Java sources reference, unless the output is a test source root (#110); that is the reason for the registration when Java tests sit next to the Kotlin ones. The poms are the source of truth.

The documentation example `example-maven-kotlin` runs the same `test-kapt` setup, with its configuration in `src/test/kotlin`. It has no Java sources and no build-helper registration: without it, `./mvnw -o -B -q clean test-compile` in that module still writes `target/test-classes/example/kotlin/model/CustomerMatcher.class`, so no registration is needed without Java tests. Its tagged `maven-test-kapt` region feeds the docs.

The plain `kapt` goal, which runs over the main sources into `kapt/compile`, is run by the three consumer builds `hamcrest-matcher-generator-endtoend-plain-kotlin/src/it/{right-scope,wrong-scope,wrong-value-type}` (their `kapt` executions). No example runs it; the Kotlin guide describes it as the special case of a configuration in the main sources.
