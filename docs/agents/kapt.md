# KAPT configuration (Kotlin end-to-end modules)

`hamcrest-matcher-generator-endtoend-mixed-kotlin-java` and `hamcrest-matcher-generator-endtoend-plain-kotlin` run the processor through the `kotlin-maven-plugin` `test-kapt` execution into `target/generated-sources/kapt/test/`. A `build-helper-maven-plugin` `add-test-source` registers that directory as a test source root, so javac compiles every generated matcher, not only the ones Java tests reference (#110). The poms are the source of truth. The documentation example `example-maven-kotlin` runs the same `test-kapt` setup, with its configuration in `src/test/kotlin`; it does not register the directory with build-helper, because a build without that registration compiles the same matchers (checked). Its tagged `maven-test-kapt` region feeds the docs. The plain `kapt` goal, which runs over the main sources into `kapt/compile`, is no longer run by any module; the Kotlin guide describes it as the special case of a configuration in the main sources.
