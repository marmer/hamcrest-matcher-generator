---
name: goRalph
description: "Run /implement-spec as an unattended loop of fresh claude -p processes, watched through a quiet monitor."
disable-model-invocation: true
argument-hint: "A spec number and limits in plain language, e.g. #410 max 5 Runden"
---

A **goRalph run** works one spec through a script, not through this session: `scripts/loop.sh` starts one fresh `claude -p "/implement-spec <spec>"` orchestrator per iteration. This session only starts the script and watches its monitor lines. Design: `docs/agents/ralph-loop.md`.

1. **Parse** the argument into the spec number (`#<n>`) and the limits, then show the parsed values in one line and go on:
   - `max N Runden` is `--max-iterations N`; `höchstens 4 Stunden` is `--max-duration 240` (minutes); `Runden höchstens 120 Minuten` is `--max-iteration-duration 120`;
   - `bis 6 Uhr` is `--until "<next 06:00 as YYYY-MM-DD HH:MM>"`, Europe/Berlin unless a zone is named (`--until "2026-11-14 06:00 America/New_York"`);
   - `--max-parallel N` (1 to 3, default 3); `--limit-stop after-iteration|after-step|now` is the stop kind a reached limit acts as (default `after-step`).
   Every limit is absent by default. A value the script cannot read ends it with an `ERROR` line and exit 2: tell the owner.
2. **Watch first**: arm the Monitor tool on `tail -n 0 -F ~/.goRalph/monitor-<spec>.log` (create the file with `mkdir -p ~/.goRalph && touch ~/.goRalph/monitor-<spec>.log` before), so an immediate `ERROR` (lock refused, bad option) is not lost.
3. **Start** the script in the background, its stdout into that file, through `bash` (no executable bit needed):
   ```bash
   bash "${CLAUDE_SKILL_DIR}/scripts/loop.sh" <spec> <limit options> >> ~/.goRalph/monitor-<spec>.log
   ```
   Use `run_in_background`. Omit an option for no such limit. The script creates the run directory `~/.goRalph/runs/<spec>-<start time>/` (control file `control.json`, `status.json`, `result-<i>.json`, `stream-<i>.jsonl`) and a lock under `~/.goRalph/locks/`; a second start for the same spec is refused with an `ERROR` line, an unfinished run of the spec is continued.
   The monitor lines (kinds, formats, exit codes) and the `status.json` fields are in `docs/agents/ralph-loop.md`. Pass nothing else on to the owner. Per line kind: `iteration ... ok` and `retro iteration ok`: do nothing; a failing retro (`ERROR retro failed`) is told to the owner in one short sentence like any `ERROR`; `WAIT`: (the 5 h 15 min cap is summed per stretch of consecutive limit hits, reset by any iteration the limit did not cut off; an assumption the owner must confirm) the script waits for a usage limit to lift (no `claude` process), tell the owner once per run in one short sentence; `ERROR` or `DENIAL`: tell the owner in one short sentence; `STOP`: caused by the owner's own stop request (`stop now`), no report; caused by `max_iteration_duration` (grace period over), tell the owner in one short sentence; `END`: (the retro iteration, #418, runs before it on every end except `stop now`) show the summary line, stop the monitor and publish the summary page (step 5).
4. **Change and stop**: edit `control.json` of the run directory on request (same keys as the options: `until`, `max_duration`, `max_iterations`, `max_iteration_duration`, `max_parallel`, `limit_stop`); the script reads it before every iteration. Stop by setting `"stop"`: `after-step` (the default, also for a request without a kind; the script ends before the next iteration, the orchestrator ends after its current work step), `after-iteration` (the running iteration finishes) or `now` (the script kills the iteration's process group; the state is the last pushed work step). A reached limit writes its stop kind itself; `max_iteration_duration` writes it during the iteration and kills the iteration after a grace period of 5 min. `status.json` shows the state on request.
5. **End: summary page**, once per run, on the `END` line only: a restart after a dead script is not an end, and there is no page during the run and no update after it.
   - Run `python3 "${CLAUDE_SKILL_DIR}/scripts/summary.py" <run directory>`. Its JSON, from `status.json` and the tracker (never the streams or results), is the only data: `duration_seconds`, `iterations`, `ok`, `failed`, `merged_prs`, `escalations`, `open_questions` (open `needs-info` tickets), `retro_tickets`. An escalation is a ticket comment that (1) mentions "escalat", (2) names a model transition (`haiku -> sonnet`, `haiku => sonnet`, a unicode arrow, `haiku to sonnet`) or (3) is a closing line `Model: sonnet|opus ...`, i.e. the ticket ran above the default model; the rule is loose on purpose.
   - Build one phone-friendly Artifact page from it: duration and counts first, then one short list with links per key; an empty list says "none".
   - Cost is deliberately not on the page.
   - If the script fails, tell the owner in one sentence and publish no page.
6. **Safety net**, from the start until the `END` line or the owner's stop (a VM stop or crash kills the script, not the run):
   - **Monitor**: re-arm the Monitor tool on the monitor log every 30 min (it times out), so it never lapses.
   - **Hourly check-in**: create ONE recurring scheduled task bound to this session (`create_trigger` with an hourly cron expression at minute 0, default self-bind; not a chain of one-shot `send_later` messages that each re-arm the next, since a firing that cannot run would end the chain). Its message to this session: read `status.json` of the run directory (no stream or result files) and tell the owner ONE short status line (`state` running, waiting for PRs or a usage limit or between; `iteration`; `ok`/`failed`); a restart is reported on top of it. If `state` is not `ended` and no `ended` file exists, start `bash "${CLAUDE_SKILL_DIR}/scripts/loop.sh" <spec> --resume-only >> ~/.goRalph/monitor-<spec>.log` with `run_in_background` (a live script refuses with "already has a running loop": do nothing; a finished run refuses with "already ended": delete the task). After a restart that started an iteration, tell the owner in one sentence that the script was dead and was restarted. The restarted script continues the run: it does not repeat finished iterations.
   - **End**: on the `END` line or when the owner stops the run, delete the task (`delete_trigger`). The same goes for a stop with `stop now`, once the script has ended.
   - Assumption, not verified: whether a firing during an active usage limit is retried or skipped; the next hourly firing is the fallback.
