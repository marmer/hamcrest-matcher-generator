---
name: goRalph
description: "Run /implement-spec as an unattended loop of fresh claude -p processes, watched through a quiet monitor."
disable-model-invocation: true
argument-hint: "A spec number and limits in plain language, e.g. #410 max 5 Runden"
---

A **goRalph run** works one spec through a script, not through this session: `scripts/loop.sh` starts one fresh `claude -p "/implement-spec <spec>"` orchestrator per iteration. This session only starts the script and watches its monitor lines. Design: `docs/agents/ralph-loop.md`.

1. **Parse** the argument into the spec number (`#<n>`) and the limits, then show the parsed values in one line and go on:
   - `max N Runden` is `--max-iterations N`; `höchstens 4 Stunden` is `--max-duration 240` (minutes); `Runden höchstens 120 Minuten` is `--max-iteration-duration 120`;
   - `bis 6 Uhr` is `--until "<next 06:00 as YYYY-MM-DD HH:MM>"`, Europe/Berlin unless a zone is named (`--until "2026-11-14 06:00 America/New_York"`);
   - `--max-parallel N` (1 to 3, default 3); `--limit-stop after-iteration|after-step|now` is the stop kind a reached limit acts as (default `after-step`).
   Every limit is absent by default. A value the script cannot read ends it with an `ERROR` line and exit 2: tell the owner.
2. **Interview**, before anything is started and only when something is open. The lister asks the tracker without a model:
   ```bash
   python3 "${CLAUDE_SKILL_DIR}/scripts/interview.py" list <spec>
   ```
   Its JSON holds `needs_info` (open `needs-info` tickets of the spec), `retro` (open tickets labelled `retro` and `ready-for-human`), `carry_over` (retro tickets accepted in an earlier interview: labelled `retro` and `ready-for-agent`, no sub-issue of the spec yet), `unfinished_run` (true when the spec has an unfinished run, which the start continues) and `interview` (true when `needs_info` or `retro` is not empty). A failing call ends with one message and exit 1: tell the owner and start nothing.
   - **Carry-over first**: only when `unfinished_run` is false (this call begins a NEW run; a call that continues an unfinished run attaches nothing, the tickets wait for the next run) and `carry_over` is not empty, run `python3 "${CLAUDE_SKILL_DIR}/scripts/interview.py" attach <spec> <n>...`. They are accepted work; this run takes them as frontier tickets. Only now, never in the interview that accepted them.
   - **Nothing open** (`interview` false): skip the interview, say so in one short line and go on to step 3 at once.
   - **One round**: read each listed ticket (body and comments) and present ALL items together in one message (one question round, not one per ticket), each with the situation in two sentences, 2 to 3 options and your recommendation. A `needs-info` ticket's options come from the question comment the loop posted. A retro ticket's options are `do` (the ticket's own options and the recommended one named) or `drop`. Wait for the owner's answers; an item the owner leaves open stays untouched.
   - **Record every answer** (the loop reads only the tracker): post it as a ticket comment (`python3 scripts/agents/issue.py comment <n> --body-file <file>`, the answer and its reason in the owner's words), then set the labels through `gh api`: `needs-info` ticket answered: `DELETE repos/marmer/hamcrest-matcher-generator/issues/<n>/labels/needs-info` and `POST .../issues/<n>/labels -f 'labels[]=ready-for-agent'`; an answer that makes the ticket obsolete closes it as not planned instead (`issue.py close <n> --reason not_planned`).
   - **Retro ticket accepted**: plan it right away. Add to its body (`PATCH`, keep the text) the acceptance criteria and the line `**Implementer model:** <haiku|sonnet|opus>` with a reason, per "Implementer model per ticket" in `docs/agents/implementation.md`; swap `ready-for-human` for `ready-for-agent`. Do NOT make it a sub-issue of the spec: the loop's frontier reads only the sub-issues, so the starting run does not take it, and the next start attaches it as `carry_over` above.
   - **Retro ticket dropped**: comment the reason, then `issue.py close <n> --reason not_planned`.
   - Answered `needs-info` tickets are sub-issues already, so they join the starting run.
   An `attach` that exits 1 names the tickets it could not attach (stderr): tell the owner in one sentence and go on. Design: `docs/agents/ralph-loop.md`; the interview text itself is not scripted.
3. **Watch first**: arm the Monitor tool on `tail -n 0 -F ~/.goRalph/monitor-<spec>.log` (create the file with `mkdir -p ~/.goRalph && touch ~/.goRalph/monitor-<spec>.log` before), so an immediate `ERROR` (lock refused, bad option) is not lost.
4. **Start** the script in the background, its stdout into that file, through `bash` (no executable bit needed):
   ```bash
   bash "${CLAUDE_SKILL_DIR}/scripts/loop.sh" <spec> <limit options> >> ~/.goRalph/monitor-<spec>.log
   ```
   Use `run_in_background`. Omit an option for no such limit. The script creates the run directory `~/.goRalph/runs/<spec>-<start time>/` (control file `control.json`, `status.json`, `result-<i>.json`, `stream-<i>.jsonl`) and a lock under `~/.goRalph/locks/`; a second start for the same spec is refused with an `ERROR` line, an unfinished run of the spec is continued.
   The monitor lines (kinds, formats, exit codes) and the `status.json` fields are in `docs/agents/ralph-loop.md`. Pass nothing else on to the owner. Per line kind: `iteration ... ok` and `retro iteration ok`: do nothing; a failing retro (`ERROR retro failed`) is told to the owner in one short sentence like any `ERROR`; `WAIT`: (the 5 h 15 min cap is summed per stretch of consecutive limit hits, reset by any iteration the limit did not cut off; an assumption the owner must confirm) the script waits for a usage limit to lift (no `claude` process), tell the owner once per run in one short sentence; `ERROR` or `DENIAL`: tell the owner in one short sentence; `STOP`: caused by the owner's own stop request (`stop now`), no report; caused by `max_iteration_duration` (grace period over), tell the owner in one short sentence; `END`: (the retro iteration, #418, runs before it on every end except `stop now`) show the summary line, stop the monitor and publish the summary page (step 6).
5. **Change and stop**: edit `control.json` of the run directory on request (same keys as the options: `until`, `max_duration`, `max_iterations`, `max_iteration_duration`, `max_parallel`, `limit_stop`); the script reads it before every iteration. Stop by setting `"stop"`: `after-step` (the default, also for a request without a kind; the script ends before the next iteration, the orchestrator ends after its current work step), `after-iteration` (the running iteration finishes) or `now` (the script kills the iteration's process group; the state is the last pushed work step). A reached limit writes its stop kind itself; `max_iteration_duration` writes it during the iteration and kills the iteration after a grace period of 5 min. `status.json` shows the state on request.
6. **End: summary page**, once per run, on the `END` line only: a restart after a dead script is not an end, and there is no page during the run and no update after it.
   - Run `python3 "${CLAUDE_SKILL_DIR}/scripts/summary.py" <run directory>`. Its JSON, from `status.json` and the tracker (never the streams or results), is the only data: `duration_seconds`, `iterations`, `ok`, `failed`, `merged_prs`, `escalations`, `open_questions` (open `needs-info` tickets), `retro_tickets`. An escalation is a ticket comment that (1) mentions "escalat", (2) names a model transition (`haiku -> sonnet`, `haiku => sonnet`, a unicode arrow, `haiku to sonnet`) or (3) is a closing line `Model: sonnet|opus ...`, i.e. the ticket ran above the default model; the rule is loose on purpose.
   - Build one phone-friendly Artifact page from it: duration and counts first, then one short list with links per key; an empty list says "none".
   - Cost is deliberately not on the page.
   - If the script fails, tell the owner in one sentence and publish no page.
7. **Safety net**, from the start until the `END` line or the owner's stop (a VM stop or crash kills the script, not the run):
   - **Monitor**: re-arm the Monitor tool on the monitor log every 30 min (it times out), so it never lapses.
   - **Hourly check-in**: create ONE recurring scheduled task bound to this session (`create_trigger` with an hourly cron expression at minute 0, default self-bind; not a chain of one-shot `send_later` messages that each re-arm the next, since a firing that cannot run would end the chain). Its message to this session: read `status.json` of the run directory (no stream or result files) and tell the owner ONE short status line (`state` running, retro (the retro iteration runs), waiting for PRs or a usage limit or between; `iteration`; `ok`/`failed`); a restart is reported on top of it. If `state` is not `ended` and no `ended` file exists, start `bash "${CLAUDE_SKILL_DIR}/scripts/loop.sh" <spec> --resume-only >> ~/.goRalph/monitor-<spec>.log` with `run_in_background` (a live script refuses with "already has a running loop": do nothing; a refusal `ERROR no run of #<n> to resume` or `ERROR run of #<n> already ended, nothing to resume` (exit 1) means there is nothing to restart: do not start again and delete the task). After a restart that started an iteration, tell the owner in one sentence that the script was dead and was restarted. The restarted script continues the run: it does not repeat finished iterations.
   - **End**: on the `END` line or when the owner stops the run, delete the task (`delete_trigger`). The same goes for a stop with `stop now`, once the script has ended.
   - Assumption, not verified: whether a firing during an active usage limit is retried or skipped; the next hourly firing is the fallback.
